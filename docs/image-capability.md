# GPT Image 2.6与GIF出口核实

核实日期：2026-11-05。结论：**用户关于Image 2.6已有原生GIF能力的判断有官方依据；本次聊天的内置入口尚未实际导出GIF。**

## 官方证据与限制

- [GPT Image 2.6 Sunburst模型页](https://developers.openai.com/api/docs/models/gpt-image-2.6-sunburst)：图像生成与编辑模型，提及动态GIF能力。不能把它当视频生成模型。
- [图像生成指南](https://developers.openai.com/api/docs/guides/image-generation#generate-animated-gif-output)：Images生成接口可设`output_format: gif`，并用`frame_count`与`frame_duration_ms`控制短动画。指南与参考页的预览帧数上限文字当前存在差异（指南2–64、参考页2–16）；不能宣称所有账号均获同一上限。
- [生成接口参考](https://developers.openai.com/api/reference/resources/images/methods/generate)：GIF预览访问需满足模型权限，具体限制仍以账号和实际响应为准。

以上页面均已打开，不只依据检索摘要。未取得本次内置入口的底层模型ID，不能声称本次实际运行的就是2.6。官方能力也不等于当前账号已有预览资格。

## 本次实际测试

工具：内置`image_gen.imagegen`，不使用API密钥，不启用其他图像插件。

要求：原创橙狐学生观察`y=x²`上的动点与切线，明确要求真实动态GIF、9帧、每帧约250ms，而非静态拼版。

读回：工具返回`.png`文件，画面为3×3分镜拼版，约1536×1024。它可以用于风格讨论，但坐标与切线不适合作精确科学图；没有用作已发布教学动画。一次失败后检查了工具schema和同routeId能力检索，当前入口只暴露prompt、参考图和背景透明设置，没有GIF输出格式、帧数或时长字段。检索候选未补足这个缺口，故未盲目重复同一请求。

## 当前实现与下一阶段

本原型采用可核算的SVG科学图层、原创对话、有限过程动画与读者步进；这些是网页动画，**不是GIF、不是视频成片**。角色目前以对话身份呈现；封面插画生图失败，本版使用原创SVG界面图形，不能把封面示意形状当作科学图。

下一阶段验证原生GIF时，使用明确支持格式参数的入口，先核实认证和GIF预览权限。可先试9帧、250ms、auto尺寸的小样（参数方案，未发起API调用）。每份输出检查文件签名、实际帧数、时间、逐帧科学性和人物一致性，再决定是否入库。若精确坐标、计数或反应关系不可靠，改由可校验图层完成；不能以“AI生成”豁免科学审核。

短GIF宜展示一个局部过程，完整漫画还需情节推进、可停止的播放和可读文字。正式视频另按用户的统一导演与OpenFilm规则制作，本轮未制作MP4或OpenFilm工程。

## 封面静态生图的网络记录

另一张独立的首页封面请求返回`network error: error decoding response body`；检查默认生成目录没有对应文件。一次更简短的内置请求重试仍返回同一错误，累计两次无可验证输出，现已停止；不能记为生成成功。此错误与GIF格式出口问题分开。本版用原创SVG知识地图界面图形，最终资产状态与散列以ASSETS.md读回为准。没有切换付费API、读取或要求用户提供密钥。
